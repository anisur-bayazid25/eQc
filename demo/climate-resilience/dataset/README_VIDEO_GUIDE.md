# eQc climate-resilience demo kit

**Entirely fictional.** All residents, transcripts, events, coding decisions and findings were written for training. No real people or research records are included. Names are invented aliases; locations provide illustrative settings only. Scripts are original English text, not translations. This package is not evidence about any community or country.

## Start here

In eQc choose **Project tools → Import**, then select **03_READY_TO_IMPORT_EQC.json**. This is the four-interview project with all three simulated coders, memos, stars, cases, groups, queries and analysis summaries. Import creates a new project; keep this original file untouched. Use **04_UNCODED_STARTER_EQC.json** to demonstrate fresh coding. The individual-coders folder contains three separate projects for an optional merge exercise.

## Suggested 10–12 minute video

1. **Questionnaire and codebook (1 minute):** show 01_questionnaire.md and 02_codebook.md; explain the fictional-data label and shared starter definitions.
2. **Import and read (1 minute):** import the ready project. Open Nasima's transcript. Show folders, passage highlighting, annotations and source memo.
3. **Codebook and quotes (2 minutes):** select Unpaid care and time; filter to Amina, inspect quote notes and starred Q8/Q11 passages. Open the uncoded starter separately to demonstrate selecting text and applying codes without disturbing the ready project.
4. **Cases, groups and queries (1 minute):** Research tools → Cases shows country, setting, age and livelihood attributes. In Review, run Water and care — overlapping codes, then the coastal or Nepal query.
5. **Analysis (2 minutes):** Frequency; Documents; Co-occurrence → select Income interruption × Debt and recurring costs; Framework → compare the Essential services and care row across all residents. Open a cell and relationship memo. Word frequencies → Generate List; KWIC → search water.
6. **Memo-Book and writing (1 minute):** select framework and code memos, use selected-only view, navigate back to a matrix, export selected Excel/Word, and export Manuscript skeleton Word.
7. **ICR (1 minute):** Analysis → ICR; retain all four documents and all three coders; choose Amina / Ravi, then another pair. Compare pairwise results with Fleiss and alpha. Explain these are synthetic agreement values, not evidence of research reliability.
8. **Consensus (2 minutes):** open Agreements for Q1/Q5/Q12 examples; then Disagreements. Find Nasima Q8, Sari Q9 and Mere Q2. Inspect code choice and selection boundaries. Explain the single-code agreement rule and multi-label review groups. Keep one coder's coding only in a disposable imported copy. Export ICR before adjudication; Undo can restore changes.

## Three coders and merge demonstration

Amina, Ravi and Lina are simulated coding identities stored on every excerpt. They are not three real authenticated accounts. Each has coding across all four transcripts. To demonstrate project merging, import individual-coders/Amina_EQC.json as a new project, then merge Ravi_EQC.json and Lina_EQC.json through the app's merge-project action. Sources match by identical names and content; code hierarchy is shared. This reconstructs the coding and attribution, but the fully prepared combined project is the one that also contains the curated analysis and writing memos.

## Intentional examples

- **Q1, Q5, Q12:** shared single-code decisions for clear agreements.
- **Q2:** Lina selects the first sentence; other coders retain event and aftermath.
- **Q8:** Ravi chooses income instead of unpaid care; discuss overlap rather than choosing by majority alone.
- **Q9:** Lina chooses eligibility instead of participation.
- **Q11:** Ravi omits the mobility child code despite discussion of moving.
- **Bangladesh Q4:** Lina omits debt, making source × code presence differ.
- **Indonesia Q6:** Ravi adds eligibility because of tenant authority.
- **Nepal Q12:** Lina misses the passage; demonstrate why Cu-alpha and consensus answer different questions.

## New temporal and clustering examples

Open Visualization → Saved drafts, then open the Histomap or Dendrogram example. Histomap uses explicit passage-level Before/Event/Early/Later tags; Dendrogram uses direct code presence across the four interviews. Both drafts start with Amina only. Inspect ⚙ settings before changing the counting or source scope. 06_period_assignments.csv is the auditable tag ledger, and analysis/histomap_counts.json contains the displayed counts.

For a clean coding demonstration, filter to Amina; use all three coders for ICR/consensus. Repeated coder assignments are not additional residents.

Coding is now uneven and sentence-based: some sentences have one code, some overlap and many are uncoded. Boundaries vary by quote and coder. Do not reuse the earlier uniform-coding screenshots or fixed agreement percentages.

## Files
